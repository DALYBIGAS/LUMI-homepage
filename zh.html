01

缓存协同

增量驻留索引、缓存的替换键和标准顺序下的热缓存复用减少主机开销。DMA 租约保护源数据。

02

三类就绪分组

显存驻留、内存命中和 SSD 回填的专家在稳定计算图中各有独立的就绪同步点，最终按原始顺序合并。

03

通过数值校验的融合

稠密层与输出头、专家与 mHC 的融合须满足布局、缩放、舍入和累加要求。

研究贡献范围

系统以 FreeToken 的服务和卸载机制及早期 LUMI 路径为基础。本文评估这些组件的协同方式，保留主机端的 SSD 完成同步点。

下载前检查磁盘空间

源权重和 FTW 存在同一块盘时，建议预留约 2.1 × 权重大小 + 20 GiB。转换会保留源文件。完整性检查及 FTW 加载成功后，可删除原始文件。

使用不同磁盘时，在 FTW 目标盘预留源权重大小 × 1.05 + 2 GiB，以及系统工作空间。可选附属文件还需要额外空间。

在自己的笔记本部署个人助理
  1. 在 LUMI 中准备模型并启动兼容 OpenAI 协议的 HTTP 服务。部分实验运行路径暂未接入 HTTP 服务。
  2. 在 LUMI 仓库根目录运行 bash apps/companion/start.sh。打开 http://127.0.0.1:8011/，填写本地 LUMI API 端口（默认 1919），查询服务并选择已加载的模型。

个人助理部署后可通过 /monitor 查看推理状态、请求耗时、资源占用和监测到的进程网络活动。请按页面注明的观测范围解读。

专用运行路径和数值校验随模型而异。当前部署的 PA 已用 Qwen3.6-35B-A3B-NVFP4 验证，其他组合需要单独验证。

05 / 复现与实验边界

结合实验条件
解读结果。

当前为研究原型，页面列出论文报告的实测结果。

“解码耗时”包括什么？

解码统计预填充后的模型前向耗时。V4.1 的解码计时不包含分词、采样及 UI/API 传输。加载、首个 logits 延迟和任务总耗时分别统计。

“8K 上下文”是否表示测过 8K 长度的输入？

除非明确报告实际输入长度，这里指分配的上下文容量。主要解码实验使用短历史。已填充状态的数值对齐检查不覆盖满长预填充性能和长文档准确率。

每条运行路径都保留原始精度吗？

V4.1 原始精度、低显存稠密缓存和 Muse 有损实验是不同配置。Muse 可选混合缓存未通过暂定数值校验。各项结果都注明了精度设置。

列出的模型都能接入 PA 吗？

接入需要已部署的 LUMI HTTP 服务、兼容的分词和工具协议。Muse 的实验运行路径尚未接入 HTTP，Qwen3.8-Flash-Next 是计划中的集成项。

iPhone 版目前进展如何？

iPhone 版的目标是在设备上离线推理。开发者可用 Xcode 构建当前源码，面向普通测试用户的签名分发仍待完成。
